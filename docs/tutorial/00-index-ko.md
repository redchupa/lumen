# 0장. Lumen 입문 — 처음부터 짜본 LLM 추론 컴파일러

> 이 책은 사이드 프로젝트로 LLM 추론 컴파일러를 처음부터 짠 6주 기록을 교육 콘텐츠
> 형태로 정리한 것입니다. ChatGPT 같은 AI 모델이 컴퓨터 안에서 정확히 어떻게
> 동작하는지, 그걸 빠르게 만드는 컴파일러를 어떻게 짜는지, 그 과정에서 어떤 측정
> 도구를 쓰는지를 단계별로 풀어 갑니다.

## 이 책이 누구를 위한 글인가

- LLM이 답을 어떻게 만드는지 막연한 분
- "Rust 코드 봤는데 어렵다"는 분
- 컴파일러 책을 펴고 절반 못 읽고 덮은 분
- GitHub 매트멀 코드를 봤는데 "무슨 말인지 모르겠다"는 분
- 사이드 프로젝트를 시작하려는데 무엇부터 짜야 할지 막막한 분

전공자 기준 학부 1~2학년 수준을 가정하고 썼습니다. 비유를 우선하고 코드는 최소
로 두었어요. 책의 추상적인 단어들이 실제 코드와 측정 데이터를 만나면 어떻게
구체적으로 보이는지가 이 책의 핵심입니다.

## 이 책이 다루지 않는 것

- 학습(training) 과정 — 이 책은 추론(inference)만 다룹니다
- GPU/CUDA 가속 — 일반 CPU 위주
- Rust 문법 — Rust 기본 문법을 알 필요는 없지만 모르면 일부 코드 예제가 어려울
  수 있어요
- 깊은 수학 — 행렬 곱셈 정도만 알면 충분

## 시리즈 구성 (10장)

각 장이 한 주제씩 독립적입니다. 그래도 순서대로 읽는 게 가장 자연스러워요. 앞장의
개념이 뒷장의 토대가 됩니다.

### 1장 — [LLM이 답을 만든다는 게 무슨 일인가](./01-llm-as-multiplication-table-ko.md)

ChatGPT가 답을 만드는 일이 컴퓨터 입장에서 정확히 무엇인지. AI 모델은 결국 거대한
곱셈표(670MB)이고, 답을 만든다는 건 그 곱셈표를 한 번 통과하는 일. 시간의 95%가
어디서 사라지는지, prefill과 decode가 무엇이 다른지.

핵심 비유: 모델 = 곱셈표 / 답 = 다음 단어 1개 고르기

### 2장 — [왜 컴파일러를 직접 짜려고 했나](./02-why-build-own-compiler-ko.md)

llama.cpp(ggml)라는 표준 도구가 이미 있는데도 처음부터 다시 짠 이유. 효율로
따지면 잘못된 결정이지만 학습 자산으로 보면 옳은 결정인 이유. 책으로 배우는
지식과 직접 짠 지식이 어떻게 다른지.

핵심 비유: 레시피 책 vs 한 번 요리해보기

### 3장 — [DSL, AST, IR — 컴파일러의 세 단계](./03-dsl-ast-ir-ko.md)

컴파일러가 사람이 쓴 코드를 어셈블리로 변환하는 4단계. DSL, AST, IR이 정확히 뭐고
왜 필요한지. 추상적 단어들 같지만 실제로는 "한국어 → 일본어 번역 3단계"와 똑같은
구조.

핵심 비유: 번역 3단계

### 4장 — [JIT — 컴퓨터가 자기 자신을 위한 코드를 짜는 마법](./04-jit-compiler-ko.md)

일반 컴파일러와 달리 프로그램 실행 중에 어셈블리를 만들어 즉시 실행하는 JIT.
"메모리에 코드를 쓰고 그걸 함수처럼 호출"이 어떻게 가능한지. 왜 LLM 추론에 잘
맞는지.

핵심 비유: 맞춤복 vs 기성복

### 5장 — [SIMD — 한 명령으로 8개를 동시에 곱하기](./05-simd-parallel-multiplication-ko.md)

CPU가 한 명령으로 여러 데이터를 동시 처리하는 SIMD 기술. AVX2, AVX-512가 무엇이고
매트멀이 빨라지는 진짜 원리. FMA(곱셈+덧셈) 명령과 4-accumulator 패턴까지.

핵심 비유: 1인분 vs 8인분 한 번에

### 6장 — [양자화 — 8비트로 압축해도 답이 같은 이유](./06-quantization-ko.md)

모델 weight를 32비트 float에서 8비트 정수로 압축해도 답이 거의 같은 이유. JPEG
사진 압축과 비슷한 아이디어인데 행렬에 적용한 것. Q8, Q4의 차이, fused matmul,
VNNI 명령어까지.

핵심 비유: JPEG 사진 압축

### 7장 — [Transformer 한 layer를 통과하면 무슨 일이 일어나나](./07-transformer-one-layer-ko.md)

1장에서 "표 한 장(layer)"이라 풀었던 것의 내부 동작. RMSNorm, Q/K/V 매트멀, RoPE,
attention, FFN의 8단계가 어떻게 흐르는지. attention의 원리를 회의실 비유로 풀어
갑니다.

핵심 비유: 회의실 5명이 발언하고 정리

### 8장 — [멀티스레딩과 메모리 벽](./08-multithreading-memory-wall-ko.md)

8 코어 CPU에서 8 스레드 가속이 8배가 아닌 1.5배밖에 안 나오는 이유. 메모리
대역폭이 코어 수와 무관한 하드웨어 한계. ThreadPool 디자인, atomic counter 패턴.

핵심 비유: 8명이 한 우물에서 물 긷기

### 9장 — [측정-주도 의사결정 — 직관 11번 중 8번이 틀렸던 이유](./09-measure-driven-decisions-ko.md)

이 책 전반에서 자주 등장한 "측정으로 부정", "11번 중 8번 부정"의 정체. 한 사이클이
정확히 어떤 모양이고, 왜 그 패턴이 사이드 프로젝트의 본질인지. 측정 인프라를
어떻게 짜야 하는지.

핵심 패턴: 가설 → 측정 → 결정

### 10장 — [6주 회고 — v0.1에서 v0.5까지](./10-six-week-retrospective-ko.md)

마지막 장. 이 책 전반의 추상적 패턴이 실제 6주 사이드 프로젝트 안에서 어떻게
흘렀는지 시간 순으로. v0.1.0(첫 토큰)에서 v0.5.0(release-tagged)까지의 일기.
무엇을 배웠는지.

## 어디서부터 읽어야 하나

가장 자연스러운 순서는 **1장부터 차례로**입니다. 1장이 큰 그림이고 그 위에서 2~9장이
디테일을 채우고 10장이 회고로 마무리.

다만 다음 패턴도 가능해요:

- **컴파일러부터 궁금하다**: 1장 → 3장 → 4장 → 5장
- **LLM 동작부터 궁금하다**: 1장 → 7장 → 6장
- **사이드 프로젝트 패턴부터 궁금하다**: 2장 → 9장 → 10장
- **빠르게 한 번 훑고 싶다**: 각 장의 마지막 "핵심 정리" 섹션만 (총 30분 분량)

전체 본문은 약 5만 자, 천천히 읽으면 5~7시간 분량입니다.

## 이 책 외에도 보면 좋은 자료

이 책은 처음 공부하는 분 대상이라 깊이가 한정적입니다. 더 깊이 들어가고 싶으면.

### Lumen 회고 블로그 시리즈 ([INDEX](../blog/INDEX.md))

이 책과 별도로 v0.1~v0.5 동안 매 phase마다 쓴 회고 17편. 더 기술적이고 디테일이
많아요. 측정 데이터, 가설 부정 사례, codegen 디테일.

### Lumen 코드 자체 ([GitHub](https://github.com/redchupa/lumen))

- `crates/lumen-dsl/`: 렉서·파서 (3장 내용)
- `crates/lumen-ir/`: IR 정의 (3장 내용)
- `crates/lumen-codegen/`: SIMD 인코더 (4장, 5장 내용)
- `crates/lumen-jit/`: JIT 캐시 (4장 내용)
- `crates/lumen-runtime/`: 텐서 연산, ThreadPool (5장, 8장 내용)
- `crates/lumen-model/`: GGUF 로더, transformer (6장, 7장 내용)

각 crate 안의 단위 테스트가 실제로 어떻게 검증하는지 좋은 학습 자료입니다.

### 외부 자료 (이 책 이후)

- *Engineering a Compiler* (Cooper & Torczon) — 컴파일러 깊이 들어가기
- *High Performance Computing* (Severance, O'Reilly) — SIMD, 캐시, 멀티스레딩
- llama.cpp 소스 코드 — 진짜 production 양자화·매트멀 커널 패턴
- Intel SDM (Software Developer's Manual) — SIMD 명령어 디테일
